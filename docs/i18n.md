# Internationalization (i18n) Guide — Browse Assist

This document describes the internationalization architecture, translation conventions, and standardized feature glossary for **Browse Assist** across all 9 supported languages.

---

## 1. Two-Layer i18n Architecture

Browse Assist uses a two-layer i18n system to cover everything from the browser's extension management page to the Popup, Options page, Content Scripts, and Background Service Worker:

1. **Manifest & Browser Shortcuts (`locales/*/messages.json`)**:
   - Powers `manifest.json` (`__MSG_extName__`, `__MSG_extDescription__`, and the 5 `cmd*` entries for browser keyboard shortcuts).
   - **Important**: Never read `package.json` (`displayName` / `description`) directly to render UI text, because Plasmo inlines the raw `__MSG_*__` tokens. Always use `t("common.appName")`, `t("common.appSlogan")`, and `t("common.appDescription")`.
2. **Runtime UI, Content Scripts & Service Worker (`src/locales/*.ts` + `rosetta`)**:
   - Single source of truth dictionary: [src/locales/en.ts](file:///mnt/Projects/BrowserExtensions/browse-assist/src/locales/en.ts) exports the `TranslationDict` type.
   - Core engine: [src/core/i18n.ts](file:///mnt/Projects/BrowserExtensions/browse-assist/src/core/i18n.ts) provides `TranslationKey` (type-safe dot-notation), `t()`, `translateFor()`, `setLocale()`, and `resolveBrowserLocale()`.
   - React hook: [src/core/useI18n.ts](file:///mnt/Projects/BrowserExtensions/browse-assist/src/core/useI18n.ts) syncs `settings.language` (`"auto"` or an explicit locale code) from `@plasmohq/storage` and updates `document.documentElement.lang`.
   - Content Scripts & Background: Watch `settings.language` changes via `storage.watch()` to call `setLocale()` in real time (including updating Context Menu labels).

## 2. Translation Conventions & Terminology

- **Application Name**: Keep **`Browse Assist`** untranslated across all languages.
- **Feature / Tool Names**: **Translate into each native language** naturally for native speakers, and **keep them 100% consistent** across every surface:
  - Popup / Options titles (`features.<key>.title`)
  - Shortcuts table (`options.shortcuts.*`)
  - Permission descriptions (`about.permissions.*`), Quick Hub actions (`features.quickHub.settings.actions.*`), and runtime error/status messages (`features.colorPicker.logic.*`)
  - Browser shortcut command descriptions (`locales/*/messages.json`)
- **Technical Terms & Proper Nouns Kept Untranslated**:
  - Formats / Technologies: `Markdown`, `HTML5`, `CORS`, `EyeDropper`, `HEX`, `RGB`, `HSL`, `PiP`, `utm_*`, `fbclid`.
  - Example product / library names: `Obsidian`, `Notion`, `GitHub`, `Konva`, `Figma`, `Maps` (in `aggressiveModeDesc`, always include all three examples `Konva, Figma, Maps` across all 9 locales).
  - Donation platforms: `Buy Me a Coffee`, `GitHub Sponsors`, `VietQR (VN Bank)`.
- **Traditional Chinese Localization (`zh_TW`)**: Use authentic Taiwanese terminology (`分頁`, `滑鼠`, `捲動`, `子母畫面`, `游標`, `螢幕`, `可視區域`, `Backspace 鍵`) rather than machine-converting from `zh_CN`.

## 4. Verification & Quality Guardrails

1. **TypeScript Compile-Time Check (`pnpm typecheck`)**:
   - Every locale file must conform to the `TranslationDict` type derived from `en.ts`.
   - All `t(...)` and `translateFor(...)` calls are type-checked at compile time via `TranslationKey`.
2. **ESLint No-Literal-String (`pnpm lint`)**:
   - `eslint-plugin-i18next` enforces `i18next/no-literal-string` (`mode: "jsx-only"`) on `.tsx` files to prevent newly hardcoded UI strings.
3. **Vitest Parity & Sanity Tests (`pnpm test`)**:
   - [src/core/__tests__/i18n.test.ts](file:///mnt/Projects/BrowserExtensions/browse-assist/src/core/__tests__/i18n.test.ts) automatically verifies:
     - 100% leaf key parity between `en` and all 8 remaining locales.
     - No empty translation values and no leaked `__MSG_` tokens.
     - 100% `{{...}}` interpolation placeholder parity against `en`.
     - Accurate `resolveBrowserLocale` mapping across regional variants (including `zh-CN`, `zh-TW`, `zh-HK`, `zh-MO`, `zh-Hant`).
4. **Build Verification (`pnpm build` & `pnpm build -- --target=firefox-mv3`)**:
   - Ensures `_locales` is packaged with all 9 languages and no raw `__MSG_extName__` tokens appear in `.js` bundles.
